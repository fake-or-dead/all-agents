# Application context evidence

People owns versioned server facts used to start an application. The only
consumer seam in this slice is:

```php
ApplicationContextEvidenceResolver::resolveForPerson(
    string $personId,
    CarbonImmutable $at,
): ApplicationContextEvidenceResolution
```

`$at` is the sole clock. Resolution selects the highest effective version.
Selection windows are half-open. Evidence resolves at `effective_at`, is stale
at the exact `stale_at`, and is superseded at a successor's exact
`effective_at`. A null `stale_at` means no independent expiry; it remains
supersedable by the next monotonic version and is not a permanent write lock.

## Finite outcomes

Statuses are type-locked by `ApplicationContextEvidenceStatus`:

- `resolved`
- `missing`
- `stale`

Reasons are type-locked by `ApplicationContextEvidenceReason`:

- `no-evidence`: no version is effective at `$at`
- `evidence-expired`: the selected version is stale at `$at`
- `unreadable-evidence`: authenticated decryption or configured-key lookup
  failed
- `invalid-evidence`: decrypted canonical facts are malformed or disagree with
  their person, version, or interval metadata

No free-form status or reason can be returned.

## Storage and encryption

`facts_encrypted` contains birth date, approved category, lay/monastic
category, and provenance together with authenticated copies of person,
version, and interval metadata. It uses Laravel `Encrypter` with
`aes-256-gcm`, a random IV, and its authentication tag. The dedicated local key
is generated by `bin/bootstrap-env`; no key or deterministic digest is stored
in Git.

Only fields required for deterministic selection and database invariants remain
in plaintext: person ID, evidence version, effective/stale interval, and
encryption key version. This leaks that a person has versioned evidence and its
validity window. It does not leak birth date, approved category,
lay/monastic category, provenance, equality of those low-entropy facts, or raw
age.

`APP_ENV=testing` may use the test `APP_KEY` when no dedicated evidence key is
configured. Local and other environments fail closed without
`PEOPLE_CONTEXT_EVIDENCE_KEY`.

The ciphertext row stores `encryption_key_version`. Live key rotation is
excluded from Issue #57. Changing or removing the configured version makes old
evidence return `unreadable-evidence`; a future rotation slice must retain old
decrypt-only keys and append newly encrypted versions before switching.

## Database invariants

PostgreSQL owns these guarantees:

- evidence is append-only; update, delete, and reparent are rejected;
- versions start at `1` and increase by exactly one per person;
- effective time increases with each version;
- explicit intervals are valid and do not overlap; an open-ended predecessor is
  implicitly closed by its successor's effective time;
- a per-person transaction advisory lock serializes concurrent inserts.

The current slice has no route, UI, writer, acquisition adapter, alumni
derivation, Course Catalog lookup, Form Context composition, or applicant
intent.
